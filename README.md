# 报价票据文档管理台

面向本地单机使用，采用 Python 3 标准库与 SQLite，不依赖网络与第三方包。

当前实现：报价单保存、按编号导出 JSON 与按编号生成 HTML 预览。

## 保存报价单

```
python3 quote.py save --db demo.sqlite --input quote.json
```

输入为 UTF-8 JSON：

```json
{
  "number": "Q-DEMO-001",
  "customer": "演示客户 <甲>&乙",
  "note": " 可选的客户说明\n支持换行 ",
  "items": [
    {"description": "咨询", "quantity": 2, "unit_price": 1250},
    {"description": "资料", "quantity": 1, "unit_price": 300}
  ]
}
```

- `number`、`customer` 为非空白字符串，`items` 为非空数组；合法文本原样保留。
- `note` 为可选的客户说明：省略或空字符串表示无说明；一旦出现就必须是字符串，
  非空内容原样保存（首尾空格与换行不删改），不参与金额计算。
- 明细 `description` 为非空白字符串，`quantity` 为正整数（布尔值不算整数），`unit_price` 为非负整数。
- 单价以**分**为单位；行金额 = 数量 × 单价，合计为各行之和，计算与存储均为整数。
- 数量及各项金额超出 SQLite 有符号 64 位整数范围时拒绝保存。
- 成功后标准输出报价编号、退出码 0；重复编号或输入无效时标准错误说明原因、非零退出，且不留下本次数据。

## 导出报价 JSON

```
python3 quote.py export --db demo.sqlite --number Q-DEMO-001
```

- 标准输出为一行完整 UTF-8 JSON 对象（末尾换行），结构与 save 的输入一致：
  包含 `number`、`customer`、`items`，每条明细包含 `description`、`quantity`、`unit_price`。
- 不输出内部标识、行金额或合计；明细按输入顺序排列，说明相同也保留为独立行。
- 数量与分单位单价保持 JSON 整数（零单价与有符号 64 位范围内的大整数精确保留），
  不转为元、浮点数或数字字符串。
- 所有用户文本与库中原文逐字符一致，说明中的首尾空格、连续空格与换行保留；
  尖括号、与号和引号只做 JSON 所需转义，不做 HTML 转义。
- `note` 仅在说明为非空字符串时出现（纯空白说明同样输出）；NULL 或空字符串说明省略。
  旧库缺少 note 列时按无说明导出，不补列、不改变已有数据。
- 命令只读取数据库、不生成文件。成功时退出码 0、标准错误为空；
  编号不存在时退出码 1、标准输出为空，标准错误说明报价编号不存在。
- 数据库不存在、不可访问、不是有效 SQLite 或缺少必要表列时同样退出 1 且不输出部分 JSON
  （兼容缺失 note 列的情况），失败不创建数据库。

## 生成 HTML 预览

```
python3 quote.py preview --db demo.sqlite --number Q-DEMO-001 --output preview.html
```

- 生成可离线打开的 UTF-8 HTML，含编号、客户、按输入顺序排列的明细、数量、单价、行金额与总计。
- 报价带有说明时，在客户信息之后、明细表格之前显示“客户说明”区域，正文保留空格与换行；无说明时不出现该区域。
- 金额统一显示为元并保留两位小数（如 1250 分显示为 12.50）。
- 所有用户文本均做 HTML 转义，显示原文，不生成标签或脚本。
- 成功后标准输出输出路径、退出码 0。编号按原文精确匹配。
- 编号不存在、输出文件已存在，或输入/数据库/输出访问失败时非零退出；前两种情况不创建或覆盖目标文件。输出目录需由调用者预先准备。

保存、导出与预览可在不同进程中运行，导出与预览只读取已保存内容（以只读方式打开数据库）。
导出的 JSON 可直接交给 save 重新保存到另一份数据库。
早期版本创建的数据库无需重建：保存时自动补充说明列，已有报价按无说明处理，可直接预览或导出。
