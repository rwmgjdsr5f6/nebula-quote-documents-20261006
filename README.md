# 报价票据文档管理台

面向本地单机使用，采用 Python 3 标准库与 SQLite，不依赖网络与第三方包。

当前实现：报价单保存、按编号生成 HTML 预览、摘要列表、按编号导出 JSON 与按客户汇总报表。

## 保存报价单

```
python3 quote.py save --db demo.sqlite --input quote.json
```

输入为 UTF-8 JSON：

```json
{
  "number": "Q-DEMO-001",
  "customer": "演示客户 <甲>&乙",
  "note": " 可选的客户说明\n支持换行 ",
  "items": [
    {"description": "咨询", "quantity": 2, "unit_price": 1250},
    {"description": "资料", "quantity": 1, "unit_price": 300}
  ]
}
```

- `number`、`customer` 为非空白字符串，`items` 为非空数组；合法文本原样保留。
- `note` 为可选的客户说明：省略或空字符串表示无说明；一旦出现就必须是字符串，
  非空内容原样保存（首尾空格与换行不删改），不参与金额计算。
- 明细 `description` 为非空白字符串，`quantity` 为正整数（布尔值不算整数），`unit_price` 为非负整数。
- 单价以**分**为单位；行金额 = 数量 × 单价，合计为各行之和，计算与存储均为整数。
- 数量及各项金额超出 SQLite 有符号 64 位整数范围时拒绝保存。
- 成功后标准输出报价编号、退出码 0；重复编号或输入无效时标准错误说明原因、非零退出，且不留下本次数据。

## 生成 HTML 预览

```
python3 quote.py preview --db demo.sqlite --number Q-DEMO-001 --output preview.html
```

- 生成可离线打开的 UTF-8 HTML，含编号、客户、按输入顺序排列的明细、数量、单价、行金额与总计。
- 正文中的报价编号、客户名与明细说明保留首尾空格、连续空格与换行（连续换行保留空行）；
  多行客户仍在客户信息区域，多行说明仍属于同一条明细，不拆成新的表格行。
- 报价带有说明时，在客户信息之后、明细表格之前显示“客户说明”区域，正文保留空格与换行；无说明时不出现该区域。
- 金额统一显示为元并保留两位小数（如 1250 分显示为 12.50）。
- 所有用户文本均做 HTML 转义，显示原文，不生成标签或脚本。
- 成功后标准输出输出路径、退出码 0。编号按原文精确匹配。
- 编号不存在、输出文件已存在，或输入/数据库/输出访问失败时非零退出；前两种情况不创建或覆盖目标文件。输出目录需由调用者预先准备。

保存与预览可在不同进程中运行，预览只读取已保存内容（以只读方式打开数据库）。
早期版本创建的数据库无需重建：保存时自动补充说明列，已有报价按无说明处理，可直接预览。

## 报价摘要列表

```
python3 quote.py list --db demo.sqlite
python3 quote.py list --db demo.sqlite --customer 演示客户 --output list.html
```

- 省略 `--output` 时输出一行完整的 UTF-8 JSON 数组（末尾换行），每张报价一个对象，
  仅含 `number`、`customer`、`total`（分单位整数），不输出说明或明细，不创建任何文件。
- 指定 `--output` 时改为生成可离线打开的 UTF-8 HTML 列表到该路径：成功后标准输出仅为
  传入的输出路径（末尾换行）、退出码 0、标准错误为空。
- HTML 页面标题与主标题均为“报价列表”，表格仅含报价编号、客户、合计（元）三列，
  每张报价一行，按编号原文 BINARY 升序排列，与保存顺序无关。
- 合计直接取库中保存值，不重新计算明细；金额精确换算为元并固定两位小数（零金额显示
  0.00，2800 分显示 28.00），有符号 64 位上限也不丢失精度，不使用浮点。
- 编号与客户做 HTML 转义后放入保留空白样式的单元格：尖括号、与号和引号显示原文，
  首尾空格、连续空格与换行可见，多行文字仍属于同一报价行，不拆成新的表格行。
- `--customer` 沿用逐字符精确匹配：大小写、空格和换行参与比较，`%` 与 `_` 按普通字符处理。
- 空库或无匹配时成功生成页面，保留表头、不显示报价行，并显示“没有匹配的报价”。
- 空字符串或纯空白的 `--customer` 在读库和创建文件前拒绝，退出 1、标准输出为空、
  标准错误说明客户筛选值不能为空白。
- 输出文件已存在时退出 1、标准错误说明输出文件已存在并带路径，不覆盖原内容；
  输出目录不存在或写入失败时退出 1、标准错误说明无法写入输出文件并带路径与原因。
- 数据库不存在、不可读、不是有效 SQLite，或缺少 quotes 表及其 number、customer、total
  任一列时退出 1、标准输出为空、标准错误说明无法读取数据库并包含路径与原因，
  失败不创建数据库或 HTML。查询全程只读，旧库缺少 note 列或 items 表时也可列出，
  不补结构、不改记录。

## 按编号导出 JSON

```
python3 quote.py export --db demo.sqlite --number Q-DEMO-001
```

- 将单张报价输出为一行完整的 UTF-8 JSON（末尾换行），结构与 save 接受的输入一致：
  `number`、`customer`、`items`，带有说明时含 `note`；不输出内部标识、行金额或合计。
- 每条明细只含 `description`、`quantity`、`unit_price`，保持输入顺序；说明相同也保留独立行。
- 数量与分单位单价保持 JSON 整数（含零单价与有符号 64 位范围内的大整数），
  不转为元、浮点数或字符串。
- 所有用户文本与库中原文逐字符一致，保留首尾空格、连续空格与换行；
  尖括号、与号和引号只做 JSON 所需转义，不做 HTML 转义。
- `note` 仅在说明非空（含纯空白）时出现；NULL 或空字符串说明省略该字段。
  旧库缺少 note 列时按无说明导出，不补列、不改动已有数据。
- 编号按原文精确匹配，空格与大小写参与匹配。命令只读取数据库、不生成文件。
- 成功时退出码 0、标准错误为空；编号不存在时退出 1、标准输出为空、
  标准错误说明报价编号不存在；数据库不存在、不可访问、不是有效 SQLite，
  或缺少必要表/列时退出 1 且不输出部分 JSON，标准错误说明无法读取数据库，
  失败不创建数据库。

导出的 JSON 可直接作为 save 的输入保存到另一份数据库；两次保存之间编号不得重复。

## 按客户汇总报表

```
python3 quote.py report --db demo.sqlite
python3 quote.py report --db demo.sqlite --customer 演示客户 --output report.html
```

- 将全部已保存报价按客户汇总为一行完整的 UTF-8 JSON 数组（末尾换行），只输出到标准输出，不生成文件。
- 指定 `--output` 时改为生成可离线打开的 UTF-8 HTML 汇总到该路径：成功后标准输出仅输出该路径（末尾换行）、退出码 0、标准错误为空；省略时保持上述单行 JSON 行为不变。
- HTML 页面标题与主标题均为“客户报价汇总”，表格每个客户一行，仅含客户、报价张数、累计金额（元）；
  客户按原文 BINARY 升序排列，与保存顺序无关。
- 所有客户行之后另以合计行收尾（三列：“合计”、本次结果报价总张数、累计金额总和，元固定两位小数）；
  合计行与客户数据行区分显示，客户原文即使就是“合计”，该客户仍作为独立客户行保留，不被替换。
  合计仅覆盖本次筛选命中的报价：每张报价计数一次（零金额同样计数），金额以库中已保存报价合计
  累加、不重新计算明细；累计超出有符号 64 位整数上限时仍精确显示。空库或无匹配时保留表头、
  不显示客户行、显示“没有匹配的报价”，合计行显示 0 张、0.00 元。
- 每个客户一个对象，仅含 `customer`（客户原文）、`quote_count`（报价张数）、`total`（累计分单位金额）；
  不输出单张编号、说明或明细。
- 客户名逐字符相同才归入同一组：大小写、首尾空格、连续空格与换行都参与比较，`%` 与 `_` 按普通字符处理。
- HTML 中客户文本做 HTML 转义后放入保留空白样式的单元格，首尾与连续空格、换行均可见，尖括号与与号显示原文，不生成标签或脚本。
- 数组按客户原文的 BINARY 升序排列，与报价保存顺序无关；客户文本只做 JSON 所需转义，解析后与保存原文一致。
- 每张报价只计数一次（含多条明细也不重复），零金额报价同样计入张数；
  累计金额以已保存的报价合计为准，不重新计算明细。
- HTML 累计金额固定显示两位小数（如 2800 分显示为 28.00），多张报价累计超出有符号 64 位整数上限时仍精确显示。
- 张数与累计金额均为 JSON 整数，不转为元、浮点数或字符串；多张报价累计超出有符号 64 位整数上限时仍精确输出。
- 空报价库或无匹配客户时，JSON 输出 `[]` 加换行；HTML 保留表头、不显示客户行，并显示“没有匹配的报价”。旧库缺少 note 列或 items 表时可直接汇总，不补表补列、不改记录。
- 成功时退出码 0、标准错误为空；空字符串或纯空白的 `--customer` 在读库和创建输出前拒绝，退出 1、标准输出为空、标准错误说明客户筛选值不能为空白。
- 输出文件已存在时退出 1、标准错误说明输出文件已存在并带路径，不覆盖原内容；输出目录不存在或写入失败时退出 1、标准错误说明无法写入输出文件并带路径与原因。
- 数据库不存在、不可访问、不是有效 SQLite，
  或缺少 quotes 表及其 number、customer、total 任一列时退出 1、标准输出为空、
  标准错误说明无法读取数据库并包含路径与原因，失败不创建数据库或 HTML。
