# 报价票据文档管理台

面向本地单机使用，采用 Python 3 标准库与 SQLite，不依赖网络与第三方包。

当前实现：报价单保存、按编号生成 HTML 预览、摘要列表、按编号导出 JSON 与按客户汇总报表。

## 保存报价单

```
python3 quote.py save --db demo.sqlite --input quote.json
```

输入为 UTF-8 JSON：

```json
{
  "number": "Q-DEMO-001",
  "customer": "演示客户 <甲>&乙",
  "note": " 可选的客户说明\n支持换行 ",
  "items": [
    {"description": "咨询", "quantity": 2, "unit_price": 1250},
    {"description": "资料", "quantity": 1, "unit_price": 300}
  ]
}
```

- `number`、`customer` 为非空白字符串，`items` 为非空数组；合法文本原样保留。
- `note` 为可选的客户说明：省略或空字符串表示无说明；一旦出现就必须是字符串，
  非空内容原样保存（首尾空格与换行不删改），不参与金额计算。
- 明细 `description` 为非空白字符串，`quantity` 为正整数（布尔值不算整数），`unit_price` 为非负整数。
- 单价以**分**为单位；行金额 = 数量 × 单价，合计为各行之和，计算与存储均为整数。
- 数量及各项金额超出 SQLite 有符号 64 位整数范围时拒绝保存。
- 成功后标准输出报价编号、退出码 0；重复编号或输入无效时标准错误说明原因、非零退出，且不留下本次数据。

## 生成 HTML 预览

```
python3 quote.py preview --db demo.sqlite --number Q-DEMO-001 --output preview.html
```

- 生成可离线打开的 UTF-8 HTML，含编号、客户、按输入顺序排列的明细、数量、单价、行金额与总计。
- 报价带有说明时，在客户信息之后、明细表格之前显示“客户说明”区域，正文保留空格与换行；无说明时不出现该区域。
- 金额统一显示为元并保留两位小数（如 1250 分显示为 12.50）。
- 所有用户文本均做 HTML 转义，显示原文，不生成标签或脚本。
- 成功后标准输出输出路径、退出码 0。编号按原文精确匹配。
- 编号不存在、输出文件已存在，或输入/数据库/输出访问失败时非零退出；前两种情况不创建或覆盖目标文件。输出目录需由调用者预先准备。

保存与预览可在不同进程中运行，预览只读取已保存内容（以只读方式打开数据库）。
早期版本创建的数据库无需重建：保存时自动补充说明列，已有报价按无说明处理，可直接预览。

## 按编号导出 JSON

```
python3 quote.py export --db demo.sqlite --number Q-DEMO-001
```

- 将单张报价输出为一行完整的 UTF-8 JSON（末尾换行），结构与 save 接受的输入一致：
  `number`、`customer`、`items`，带有说明时含 `note`；不输出内部标识、行金额或合计。
- 每条明细只含 `description`、`quantity`、`unit_price`，保持输入顺序；说明相同也保留独立行。
- 数量与分单位单价保持 JSON 整数（含零单价与有符号 64 位范围内的大整数），
  不转为元、浮点数或字符串。
- 所有用户文本与库中原文逐字符一致，保留首尾空格、连续空格与换行；
  尖括号、与号和引号只做 JSON 所需转义，不做 HTML 转义。
- `note` 仅在说明非空（含纯空白）时出现；NULL 或空字符串说明省略该字段。
  旧库缺少 note 列时按无说明导出，不补列、不改动已有数据。
- 编号按原文精确匹配，空格与大小写参与匹配。命令只读取数据库、不生成文件。
- 成功时退出码 0、标准错误为空；编号不存在时退出 1、标准输出为空、
  标准错误说明报价编号不存在；数据库不存在、不可访问、不是有效 SQLite，
  或缺少必要表/列时退出 1 且不输出部分 JSON，标准错误说明无法读取数据库，
  失败不创建数据库。

导出的 JSON 可直接作为 save 的输入保存到另一份数据库；两次保存之间编号不得重复。

## 按客户汇总报价

```
python3 quote.py report --db demo.sqlite
```

- 只读报表，只输出到标准输出、不生成文件：成功时退出码 0、标准错误为空，
  标准输出是一行完整的 UTF-8 JSON 数组并以换行结束；空报价库输出 `[]` 加换行。
- 每个客户只对应一个对象，对象仅含 `customer`、`quote_count`、`total`，
  分别表示客户原文、报价张数与累计分单位金额；不输出单张编号、说明或明细。
- 客户名逐字符相同才归入同一组：大小写、首尾空格、连续空格与换行均参与比较，
  `%` 与 `_` 按普通字符处理。
- 数组按客户原文的 SQLite BINARY 升序排列，与报价保存顺序无关。
- 客户文本只做 JSON 所需转义，解析后与保存原文一致；张数与金额均为 JSON 整数，
  不转为元、浮点数或字符串。
- 每张报价只计数一次，即使含多条明细也不重复计数；零金额报价同样计入张数。
- 累计金额以已保存的报价合计为准，不重新计算明细；多个合法报价累计超过
  有符号 64 位整数上限时仍精确输出。
- 兼容缺少 note 列的旧库，读取前后数据库结构和已有记录保持一致。
- 数据库不存在、不可访问、不是有效 SQLite，或缺少 `quotes` 表及其
  `number`、`customer`、`total` 任一列时，退出码为 1，标准输出为空，
  标准错误说明无法读取数据库并包含路径和原因，且不创建数据库。
